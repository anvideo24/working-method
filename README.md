# working-method

일하는 방식의 정본이다. 어떤 도구(Cursor·ChatGPT·Claude 등)든, 어떤 제품이든 여기서 읽는다.

| 파일 | 무엇 | 언제 고치나 |
|---|---|---|
| `AGENTS.md` | 일을 시작하고 끝내는 법. 읽는 순서와 되돌려 적는 자리 | 순서나 자리가 바뀔 때 |
| `RULES.md` | 어디에나 해당하는 제품 규칙. 돈·승인·AI 권한·이력·비밀 | 제품이 지켜야 할 것이 바뀔 때 |
| `HOW.md` | 일하는 방식. 일을 받았을 때, 판단할 때, 끝낼 때 | 일하는 방식이 바뀔 때 |
| `LESSONS.md` | 배운 것. 압축해서 적는다. 일기처럼 쌓지 않는다 | 같은 실수를 두 번째 겪지 않게 하려 할 때 |

## 층 구조

1. **공용** (이 저장소) — 어디에나 해당하는 것
2. **제품** (각 제품 저장소의 `RULES.md`) — 그 제품만의 차이. 공용을 붙여넣고 고치지 않는다
3. **사람용 화면** — 제품이 git 원본을 읽어 보여 준다. 화면용 사본을 정본으로 두지 않는다

겹치면 그 제품 `RULES.md`가 그 제품의 정본이다.

## 왜 이렇게 나눴나

규칙만 적어 두면 새 상황에서 왜 그런지 몰라 엉뚱하게 적용된다. 이유를 남긴다.

**왜 공용을 따로 뒀나.** 같은 규칙을 제품마다 베껴 두면 하나를 고쳐도 나머지가 안 따라온다. 시간이 지나면 어느 쪽이 맞는지 아무도 모른다. 그래서 어디에나 참인 것은 한 곳에만 둔다.

**왜 제품이 이기나.** 공용은 「어디서나 참인 것」만 담는다. 그 제품이 **지금** 어떻게 동작하는지는 그 제품만 안다. 공용이 제품을 이기면, 현실과 다른 규칙이 제품의 발목을 잡는다. 그래서 겹칠 때는 제품이 정본이다.

**왜 붙여넣지 말라고 하나.** 붙여넣는 순간 원본이 둘이 된다. 둘은 반드시 갈라지고, 갈라진 것은 조용히 갈라진다. 에러도 경고도 없다.

**왜 화면이 git을 읽나.** 화면용 사본을 따로 두면 화면과 저장소가 갈라진다. 누가 언제 왜 고쳤는지도 사라진다. 화면은 보여 주기만 하고, 고치는 것은 커밋으로 한다.

**왜 이유를 적나.** 규칙은 그대로 굳지만 이유를 알면 새 상황에서 스스로 고를 수 있다. 「이렇게 해라」가 아니라 「지금 이렇고 까닭은 이것이다」로 적는 이유다.

## 어디서 보나

| 누가 | 어디 | 무엇이 보이나 |
|---|---|---|
| 사람 | 그 제품의 관리자 매뉴얼 화면 | `RULES` · `HOW` · `LESSONS` 셋 |
| 사람 | GitHub `anvideo24/working-method` | 다섯 개 전부. 공개라 로그인 없이, 휴대폰에서도 |
| 사람 | 아래 「클론 위치」의 로컬 폴더 | 다섯 개 전부 |
| 도구 | 제품 `AGENTS.md`가 가리키는 그 클론 | 다섯 개 전부 |

관리자 화면에 `AGENTS.md`와 `README.md`는 안 나온다. 사람이 읽을 설명이 아니라 도구용 이정표라 일부러 뺐다.

⚠️ **화면은 그 기계의 로컬 클론을 읽는다.** GitHub에서 직접 받아오지 않는다. 그래서 클론이 없는 서버에 제품을 올리면 공용 칸은 「아직 없다」로 뜬다. 빈 화면으로 두지 않고 그렇게 밝히는 것이 규칙이다. 서버에서도 보이게 하려면 배포할 때 같이 싣거나, 그때 GitHub에서 읽어 오게 바꾼다.

## 클론 위치

- Windows: `C:\dev\working-method`
- Mac: 제품 저장소와 같은 부모 폴더의 `working-method`

## 도구에 물리는 법

- **Cursor·Claude Code**: 제품 저장소의 `AGENTS.md`가 이 저장소를 가리키면 된다. 그 파일이 여기 `AGENTS.md`로 이어진다.
- **ChatGPT처럼 저장소를 못 읽는 도구**: [AGENTS.md](AGENTS.md) 4절의 부트 문구를 지침 칸에 붙인다.

부트 문구의 원본은 `AGENTS.md` 한 곳뿐이다. 여기에 옮겨 적지 않는다 — 두 곳에 적히면 어긋난다.

## 넣지 않는 것

실데이터, 비밀번호, API 키, 실제 서버 주소, 고객사명, 이메일, 특정 제품의 화면 구조. 이 저장소는 공개다.

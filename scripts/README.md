| 파일 | 무엇 |

## 합격표 — 맡길 때 같이 주는 것

`HOW.md` 3절: *「맡길 때 합격 조건을 같이 준다. 써야 할 이름, 건드릴 파일, 통과할 명령, 떠야 할 화면.」*

그 조건을 **파일로** 남긴다. 말로만 주면 돌아온 것을 사람이 읽어서 채점하게 되고, 그건 요리사가 쓴 자기 평가서를 읽고 통과시키는 것이다.

```json
{
  "id": "260907-recall-hook-trim",
  "task": "회수 훅 발췌를 3500 → 1200 으로 줄인다",
  "checks": [
    { "name": "값이 바뀌었다",
      "file": "path/to/file.py", "contains": "MAX_FILE_BYTES = 1200" },

    { "name": "옛 값이 남아 있지 않다",
      "file": "path/to/file.py", "absent": "MAX_FILE_BYTES = 3500" },

    { "name": "산출물이 실제로 생겼다",
      "exists": "path/to/output.json" },

    { "name": "실호출로 돈다",
      "run": "python hook.py",
      "stdin": "{\"prompt\":\"시험 문장\"}",
      "expect_exit": 0,
      "expect_stdout": "hookSpecificOutput" }
  ]
}
```

**돌리는 법**

```
python scripts/grade.py 합격표.json            # 채점
python scripts/grade.py 합격표.json --dry-run  # 무엇을 돌릴지만 본다
python scripts/grade.py 합격표.json --quiet    # 낙제만 본다
```

전부 통과 `0` · 하나라도 낙제 `1` · 합격표가 잘못됨 `2`.

**검사 네 가지**

| 쓰는 것 | 무엇을 보나 |
|---|---|
| `run` (+`stdin`·`expect_exit`·`expect_stdout`·`reject_stdout`·`cwd`·`timeout`) | 명령을 돌려 통과·실패를 가른다 |
| `exists` | 산출물이 **실제로** 있는지 본다. 「됐습니다」 말고 실물 |
| `contains` + `file` | 파일 안에 있어야 할 것 |
| `absent` + `file` | 파일 안에 **없어야** 할 것 (옛 값·지웠어야 할 줄) |

## 🔴 첫 판에서 실제로 물린 것 두 가지

**하나 — 종료 코드만 보면 「조용한 성공」을 놓친다.**
명령이 `0` 을 돌려주는데 출력이 비어 있을 수 있다. 그래서 `run` 검사에 `expect_stdout` 이 없고 출력도 비면 **낙제로 본다.** 통과 딱지는 증거가 아니다.

**둘 — 파이프를 쓰지 마라. `stdin` 을 써라.**
`echo {...} | prog` 는 윈도우(`cmd.exe`)와 맥·리눅스(`sh`)에서 따옴표 처리가 다르다. 2026-09-07 첫 판에서 실제로 물렸다 — `cmd.exe` 가 JSON 따옴표를 먹어 **종료 코드는 0인데 입력이 안 들어갔다.**

## 쓰는 흐름

1. **맡기는 쪽**이 합격표를 쓴다. 일을 시작하기 **전에** 쓴다 — 나중에 쓰면 결과에 맞춰 조건을 낮추게 된다.
2. **맡은 쪽**은 합격표를 고치지 않는다. 고쳤으면 그건 채점이 아니다.
3. 돌아오면 **채점기를 먼저 돌린다.** 지휘하는 쪽이 읽을 것은 통과 목록이 아니라 **낙제 이유뿐**이다.
4. 낙제하면 **재시도부터 하지 않는다.** 실패는 종류가 다르고, 종류마다 갈 곳이 다르다. 같은 방식으로 두 번 실패하면 방식 자체를 바꾼다.
